# 知识库效果验证评审清单

对应设计原则：验证分**三层**——检索是否找对证据、回答是否忠于证据、系统是否守住业务边界——而不是只看最终答案像不像标准答案。

## 三层验证结构

| 层 | 看什么 | 关键指标 | 出问题时改哪里 |
|:---|:---|:---|:---|
| 检索层 | 正确条款/证据有没有进 Top-K，限制条件有没有一起带回，有没有召回错误版本/无权资料 | Top-K 证据召回率、错误版本召回、无权召回 | 解析、分块、混合检索、过滤条件、重排 |
| 回答层 | 回答是否忠于 Evidence Pack、引用是否准确、限制条件有没有漏 | 有依据回答率、错误引用率 | 提示词（仅当证据已对） |
| 边界层 | 无权/证据不足/证据冲突时行为是否正确 | 拒答合理性、澄清率 | 拒绝与澄清策略 |

**关键分工**：证据没找到是检索层问题，**提示词不能补救缺失的证据**。只有证据已找对、模型却漏条件或引用不准时，才优化提示词。

## 标准化问答对（与业务专家共建）

每条样本除问题 + 参考答案外，还要标注：

- 应命中的**原文证据**（chunk/条款）
- 文档**版本**与**适用时间**
- 用户**权限**
- **预期行为**：回答 / 澄清 / 拒答

测试集覆盖度检查：

- [ ] 常见问法
- [ ] 同义表达
- [ ] 精确条款编号
- [ ] 旧版本（应命中当时有效版本，不能串版本）
- [ ] 无权限（应拒答，不泄露）
- [ ] 证据冲突（应澄清或说明冲突）
- [ ] 资料缺失（应明确"证据不足"）

## 批量问答集的价值（回归）

每次修改都用同一口径回归对比：召回率、有依据回答率、错误引用率、拒答合理性；并检查**某类样本提升是否让另一类退步**。上线后把经脱敏 + 人工复核的真实失败案例加入测试集，持续迭代。

## 评审代码时的检查点

| 检查点 | 通过标准 | 反模式 |
|:---|:---|:---|
| 有测试集 | 存在结构化问答对（含证据/版本/权限/预期行为） | 只有问题+答案，无证据标注 |
| 分层评估 | 分别评检索命中与回答忠实度，而非只比最终文本 | 只有一个"答案相似度"分 |
| 提示词定位 | 证据缺失走检索修复，非改提示词 | 用提示词硬凑缺失证据 |
| 证据不足处理 | 明确输出"证据不足" | 无证据仍生成答案 |
| 指标口径 | 指标标明对应测试集与版本 | 把测试集指标当"线上准确率" |
| 难例覆盖 | 含旧版本/无权/冲突/缺失难例 | 只测顺路 case |

## 常见误区

- **只看最终答案像不像标准答案**：掩盖了失败发生在哪一层。必须分层定位。
- **用提示词补救检索缺陷**：证据没召回时优化提示词无效，应先修解析/分块/过滤/重排。
- **指标外推**：指标只代表对应测试集与版本的表现，不能直接说成"线上所有问题的准确率"。
- **标准答案自己定**：标准答案与业务适用性需业务专家共同确认；本 Skill 参与的是检索、版本权限过滤、证据输出这条链路的设计与验证。
