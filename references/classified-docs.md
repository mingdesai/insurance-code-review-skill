# 涉密 / 非涉密文档共存 —— 双层安全兜底评审清单

对应设计原则：**同一向量库里涉密与非涉密文档共存时，检索前限制候选范围，检索后用权威权限数据逐条复核**。不能只靠向量相似度排序，也不能把 Milvus 里的权限标签当最终授权依据。

## 双层结构

```
用户查询
  │  登录身份 → 权限服务 → 当前授权范围
  ▼
第一层｜检索前过滤（在 Milvus 内缩小候选）
  租户 / 组织 / 部门 / 密级 / 可见范围 / 发布版本
  前端传的密级、部门参数不能扩大范围
  ▼
Milvus 返回 chunk_id
  ▼
第二层｜检索后权威复核（逐条）
  当前是否仍有权限？密级是否允许？版本是否已发布？资料是否已撤回？
  ✔ 通过 → 重排 → Evidence Pack → 大模型上下文
  ✘ 不通过 → 直接丢弃，标题/摘要/片段内容都不返回给前端
  ▼
证据不足？→ 在授权范围内补召回；仍不足 → 明确说"证据不足"，不放宽权限凑答案
```

## 评审检查点

| 检查点 | 通过标准 | 反模式严重程度 |
|:---|:---|:---|
| 两层都在 | 检索前过滤 + 检索后复核同时存在 | 只有一层 → 严重~阻断 |
| 授权来源 | 后端按登录身份从权限服务取授权 | 用前端密级/部门参数放宽 → 阻断 |
| 复核维度 | 权限 + 密级 + 发布版本 + 撤回 四项都查 | 漏查撤回/版本 → 严重 |
| 丢弃彻底 | 未通过项标题、摘要、片段全部不返回 | 返回标题/摘要"脱敏预览" → 阻断 |
| 缓存 | 缓存结果也经同样复核 | 缓存直接返回未复核 → 严重 |
| 证据不足 | 明确告知不足，不放宽权限 | 放宽权限凑答案 → 阻断 |
| 物理隔离 | 若安全制度要求独立环境/独立库，同库双层不替代物理隔离 | 用同库双层规避物理隔离要求 → 需提示合规风险 |

## 反模式与修复

### 反模式：只做第一层就喂大模型（严重）

```python
# ❌ 检索前过滤后直接进上下文
hits = collection.search(emb, expr=expr, limit=k)
context = [h.text for h in hits]          # 缺第二层：入库标签可能错、索引可能滞后、权限可能已变
answer = await llm.generate(query, context)
```

```python
# ✅ 检索后逐条回权威源复核，未通过的彻底丢弃
hits = collection.search(emb, expr=expr, limit=k)
evidence = []
for h in hits:
    meta = await catalog.get(h.chunk_id)
    ok = (await perm_service.can_read(user, meta)          # 当前权限
          and perm_service.clearance_ok(user, meta.classification)  # 密级
          and meta.publish_status == "published"           # 已发布
          and not meta.revoked)                            # 未撤回
    if not ok:
        continue                                           # 连标题摘要都不返回
    evidence.append(h)

if not _enough(evidence):
    evidence += await _recall_more(user, query)            # 授权范围内补召回
if not _enough(evidence):
    return "证据不足，无法作答"                              # 不放宽权限凑答案
```

### 反模式：把向量库标签当最终授权（阻断）

Milvus 里的密级/部门标签是**缩小候选**用的，不是最终判定。最终授权必须回权威权限服务/目录。入库标签可能写错或滞后。

### 反模式：给前端"脱敏预览"（阻断）

未通过复核的片段，标题、摘要、来源都不能返回——它们本身也可能泄密。

## 防的两类问题

1. **入库标签错误或索引更新延迟**：第二层回权威源复核挡住。
2. **用户权限或文档状态在检索后发生变化**：第二层用"当前"状态复核挡住。

## 边界

涉密资料若企业安全制度要求独立环境或独立库，**同库双重过滤不能替代物理隔离**——评审时应提示该合规约束。代码职责是把检索链路的权限校验与拒绝策略落实到位；文档定密与授权规则由业务及安全管理方确定。
